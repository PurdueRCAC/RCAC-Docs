# Research 04 — Importer design and reproducibility

Scope: how the one-off port is executed so it is reproducible (R8), re-runnable for the
touch-up sync, and checkable by each phase's `verify:`.

## Where it lives

- `tools/hubzero/import_docs.py` plus `tools/hubzero/import.yml` (config) and
  `tools/hubzero/README.md` (how to run it, and when to retire it). `tools/` is where the
  site's other generators live (`generate_breadcrumbs.py`, `generate_agent_context.py`), and
  the touch-up sync needs the importer in-repo. `tools/**` is high-impact, so review findings
  on it get a human gate. That is appropriate.
- Dependencies: stdlib plus `pyyaml` (already in `.venv` via mkdocs). Python 3.14 in `.venv`.

## Config

```yaml
# tools/hubzero/import.yml
repo: https://github.com/hubzero/hubzero-cms
commit: 9c1a8c678002bdfb41860f90915a3589ab60339e
books: [tools]          # grows phase by phase; final: all five
```

The source clone path comes from `$HUBZERO_CMS` (no machine path in the repo). The importer
reads every file with `git -C $HUBZERO_CMS show <commit>:<path>` (and `ls-tree -r` for the
listing), **never the working tree**, so a clone that has moved on still reproduces the port.
If the commit is absent (the clone is shallow), it fails with the `git fetch --depth=1 origin
<sha>` hint.

## Commands

- `import`: deletes and regenerates `docs/hubzero/**` and `docs/assets/images/hubzero/**`,
  and rewrites the `mkdocs.yml` region between
  `# >>> hubzero nav: generated by tools/hubzero/import_docs.py; do not edit by hand` and
  `# <<< hubzero nav`. The deletion removes pages that disappeared upstream. It touches nothing
  else.
- `check`: the phase gate for R2, R3, R4, R5, R6, R7, R8:
  1. **R8**: import into a temp tree and byte-compare it with the committed `docs/hubzero/`,
     the images, and the nav region.
  2. **R2**: every source page in the configured books (plus the four root pages) maps to
     exactly one output whose H1 equals the source H1.
  3. **R6/R7**: every output has `hubzero.upstream`, `hubzero.commit`, and `hubzero.status`
     front-matter, and no output body contains the `<!--` metadata header.
  4. If `site/` exists (the `verify:` builds first): **R3** fragment and relative links inside
     `site/hubzero/` resolve; **R4/R10** every `<img>` has non-empty `alt` and an existing
     `src`; **R5** each `reference/api` page renders an `h2` with an id for every
     `## METHOD /path` in its source (245 endpoints in total).
  Exit 0 when everything passes, 1 with a findings list otherwise.

## Determinism rules

Sorted traversal; no timestamps or run metadata in outputs; `yaml.safe_dump(…, sort_keys=False)`
with a fixed key order (`tags`, `render_macros`, `description`?, `hubzero`); every value a
string (so `reviewed: '2026-10-01'` is not re-typed to a date); LF line endings; images copied
byte-for-byte; nav labels quoted by the YAML dumper.

## Transform pipeline (per page)

1. Parse and strip the HTML-comment header (R7) and build the front-matter (R6).
2. Expand `<!--include:…-->` from the pinned commit (02).
3. Rewrite links and images (03).
4. Add explicit heading ids where needed (03, 05).
5. Normalize the measured dialect gaps: re-indent nested list items to 4 spaces, and insert a
   blank line before a list that follows a paragraph (02). These are mechanical changes, not
   content edits; each one is listed in the importer's report.
6. Map the path (prefix strip, `README.md` → `index.md`, the collision rule) and write.

Nav: books in `site.json` order. Within a book, sections and pages are sorted by
`order_key_for()` (order meta → prefix → name). Each label is the page or section H1 rendered
to plain text. Each section's first child is its bare `index.md`.

## Review-status display (R6): front-matter is the single source

The banner and stamp are rendered at build time from `page.meta.hubzero.status`, by
`on_post_page_macros(env)` in `main.py`. It runs even with `render_macros: false` (01). The
texts mirror upstream's `build_status_banner` / `build_review_stamp`, as Material admonitions:
`!!! warning "Not yet reviewed"` / `!!! warning "Draft"` at the top, and an italic stamp line
at the bottom. Why not have the importer bake the text into the body: maintainers would have
to edit the front-matter **and** the prose to change a status. STYLE.md's workflow is to flip
one header field. Keeping that one-field workflow is what makes "the HUBzero team maintains
these pages here" workable.

## After the handover

Once the HUBzero team edits a page, `check`'s R8 comparison fails by design: the importer has
done its job. `tools/hubzero/README.md` states that a touch-up re-import must happen **before**
hand edits begin (or be reconciled by hand afterwards). After the handover the importer and its
nav markers can be deleted, leaving ordinary hand-maintained nav.
